Execution and Handover

Outputs produced

  • Upload link Tokenised, mobile-friendly client upload link per case — no app installation required.
  • Tracker record Chase record in Google Sheets: client, policy, missing fields, stage, last contact, consent.
  • Party notification Insurer and loss adjuster notified via webhook; shared milestone status per role.
  • Exception queue Cases >7 days routed to senior review with 24-hour SLA and recommended action.

Testing approach

The workflow runs against bundled synthetic demo data (8 customer requests, 6 leads, 7 policies, 7 M-Pesa transactions, 5 insurer statements, including deliberate edge cases such as an unmatched payment and an expired policy). No real client data is used, no live webhook is executed during the demo, and no credentials are hard-coded — secrets go through n8n’s credential system.

Error handling

  • Gmail sends Use continueErrorOutput — a failed send is logged to the tracker rather than halting the chase.
  • Dashboard fallback The broker dashboard falls back to localStorage-only mode when the n8n webhook is unavailable — the UI keeps working offline.
  • Send errors Logged to the tracker sheet with the failed client and channel for manual follow-up.

Deliverables included

  • Workflow WB-08 Document Chasing Escalation (n8n workflow definition, importable).
  • Dashboard BrokerFlow document-chase dashboard (case create, case list, multi-party milestone tracker, communication history).
  • Client upload Tokenised, mobile-friendly upload page.
